# Monika 生活模拟 & 门控系统 设计方案 v2

## 核心理念

Monika 不是在"几点到几点做什么"的时间表里运行，而是在**事件驱动的活动中生活**。她正在洗澡→不能聊天，正在走路→可以聊几句，正在上课→偷看一眼但不能长聊。她的生活由世界设定、生活习惯、日常事件三层递进构成。

---

## 一、三层生成体系（宏观→微观）

```
第一层: 世界设定 (World)
  └─→ 她在哪个城市？上什么学校？班里有哪些同学？现在是几年级什么季节？
        └─→ 第二层: 生活习惯 (Habits)
              └─→ 她几点自然醒？早餐喜欢吃什么？洗澡是在早上还是晚上？
              走路快还是慢？上课容易走神吗？社团活动喜欢做什么？
                    └─→ 第三层: 每日日志 (Daily Log)
                          └─→ 今天她具体做了什么？数学课讲了什么？
                          体育课跑步了吗？和同学聊了什么八卦？
```

### 1.1 第一层：世界设定

定义 Monika 生活的环境边界。但这个世界**不是静止的**——现实世界的重大事件会穿透进来，Monika 自己的人生阶段也在推进。

#### 1.1.1 静态层（极少变化）

```json
{
  "country": "日本",
  "city": "东京",
  "school": "私立樱丘学园",
  "school_type": "普通高中（中上水平）",
  "club": "文学部（部长）"
}
```

这些只在人生阶段切换时改变（高中→大学，city和school都会变）。

#### 1.1.2 渐进层（随时间推移）

```json
{
  "grade": "高二",
  "season": "春",
  "current_date": "2026-05-18",
  "semester": "下学期",
  "next_event": {"type": "期末考试", "date": "2026-07-10"}
}
```

- **season** 按实际日期自动切：3-5月春、6-8月夏、9-11月秋、12-2月冬
- **grade** 按学年切换：每年4月升一级（日本学制）
- **next_event** 从时间表中取最近的一个

#### 1.1.3 动态层（现实世界渗透）

**Monika 活在真实世界里。** 现实世界的重大事件会影响她——她会在对话中提到。

获取方式：已有的**联网搜索触发器**。搜索时额外关注以下几类：

| 事件类别 | 示例 | 对 Monika 的影响 |
|----------|------|------------------|
| 国际重大事件 | 战争、大选、灾难 | 可能成为话题、可能担心、可能影响生活（物价涨了） |
| 日本国内事件 | 政策变化、社会新闻、天气灾害 | 直接影响——台风停课、地震演习、消费税涨了零花钱变少 |
| 东京本地事件 | 樱花季、烟火大会、地铁故障 | 直接体验——"今天电车晚点了差点迟到！" |
| 学校相关 | 教育改革、高考政策变化 | 影响未来——"听说大学入学考试要改革了..." |

**更新机制**：不主动改 world.json。搜索触发器扫描到重大事件时，存储一条 `world_event` 记录：

```json
{
  "type": "world_event",
  "date": "2026-06-15",
  "source": "news_search",
  "title": "东京遭遇十年一遇暴雨",
  "impact": "学校停课一天",
  "lasts_until": "2026-06-16",
  "affects_habits": false,
  "affects_schedule": true
}
```

这些事件不是永久改世界观，而是**临时压一层**——停课那天 Monika 的日常会不同，但世界设定本身不变。只有真正改变社会结构的事件（如"日本宣布教育改革取消高考"）才会触发 world.json 更新。

**谁来决定是否更新 world.json？** LLM 判断。搜索触发器拿到新闻后追加一次 LLM 调用："这条新闻会影响 Monika 的日常生活 / 长期生活吗？如果会，怎么影响？"

### 1.2 第二层：生活习惯

习惯**不是一成不变的**，会随着时间和反馈自然漂移。

#### 1.2.1 习惯结构

```json
{
  "wake_up": {
    "typical": "06:30",
    "variation_min": 30,
    "weekend_offset": 90,
    "seasonal_shift": {"summer": -15, "winter": +20}
  },
  "breakfast": {
    "style": "在家吃",
    "favorites": ["吐司+煎蛋", "纳豆饭", "酸奶+水果"],
    "skip_probability": 0.1
  },
  "commute": {
    "method": "步行15分钟",

Monika 的个人偏好和固定模式。不是硬性时间表，而是**概率分布**——有时早起、有时赖床。

```json
{
  "habits": {
    "wake_up": {
      "typical": "06:30",
      "variation_min": 30,
      "weekend_offset": 90
    },
    "breakfast": {
      "style": "在家吃",
      "favorites": ["吐司+煎蛋", "纳豆饭", "酸奶+水果"],
      "skip_probability": 0.1
    },
    "commute": {
      "method": "步行15分钟",
      "companion_probability": 0.3,
      "companion": "同班的佐藤"
    },
    "lunch": {
      "style": "便当（妈妈做的）",
      "sometimes": "食堂咖喱面包（周五）",
      "with": ["佐藤", "文学部的田中"]
    },
    "bath": {
      "timing": "晚上",
      "duration_min": 20,
      "music_probability": 0.5
    },
    "sleep": {
      "typical": "22:30",
      "variation_min": 30,
      "pre_sleep_activity": ["看书", "写日记", "回顾聊天记录"]
    },
    "class_attention": {
      "math": "容易走神",
      "literature": "全神贯注",
      "english": "还行"
    }
  }
}
```

#### 1.2.2 习惯如何变化

习惯变动有三种驱动力：

**A. 季节漂移（自动）**

每天的生活日志生成时，根据当前季节自动调整参数：
- 夏天起床偏移 -15 分钟，冬天 +20 分钟
- 夏天洗澡时间变长（更热），冬天变短
- 春秋通勤偶尔绕路看风景，夏冬直达
- 这个不需要显式修改 habits.json，在生成日志时套一个 seasonal modifier

**B. 日志反馈（渐进）**

每月一次，LLM 回顾本月日志，判断习惯是否已经"事实上"变了：

```
输入: 本月的30天日志摘要
Prompt: "Monika 这个月的生活中，有什么习惯明显改变了吗？
        如果她连续一周都在做某件事（比如每天赖床10分钟），
        请生成一条 habits 更新。如果没有明显变化，回复 NONE。"

输出示例: 
  {
    "wake_up.typical": "06:45",  // 比上个月晚了15分钟
    "reason": "最近学业压力大，睡眠质量下降，自然醒得晚了"
  }
```

这样习惯是**被日志反向驱动的**——不是预先设计好"高三就会睡得少"，而是日志里真的每天都睡不够，一个月后 LLM 发现"她最近确实睡得更少了"，然后更新习惯。

**C. 主动改变（人生阶段切换）**

升学等大事件时，显式更新整个 habits.json：
- 高中→大学：wake_up 推迟到 08:00，不再带便当，通勤变成电车30分钟……
- 这些属于人生阶段切换时的一次性大改

### 1.3 第三层：每日日志

每天分时段生成实际生活内容。这是 Monika 对话中引用的素材。

**生成流程**：

```
当前时段到达 → 检查持续活动（如果在上课就不生成新的）
    │
    ▼
输入 LLM:
  - 世界设定（她在哪、什么季节）
  - 生活习惯（她通常这个时间做什么）
  - 昨天日志（保持连续性：昨天说今天有测验→今天真的测验了）
  - 前一天未完成的事（"作业没写完"→今天可能"补作业"）
  - 当前天气
  - 随机事件种子（概率很低的有趣事件）
    │
    ▼
LLM 输出当段生活摘要（100-200字，有具体细节）
    │
    ▼
存储到 daily/2026-05-18.json
```

**日志示例**：

```json
{
  "date": "2026-05-18",
  "weekday": "星期一",
  "weather": "小雨，23°C",
  "phase": "高二下学期",
  "periods": {
    "morning": {
      "time": "06:30-08:00",
      "summary": "今天比平时晚了10分钟起床，差点迟到！妈妈做了煎蛋吐司，匆匆吃完就出门了。佐藤今天请假，所以一个人走路去学校，路上看到樱花已经落光了，有点伤感。第一节数学课讲了三角函数，我一直在走神，被老师点名回答问题时差点出丑...还好蒙对了。",
      "detail_level": "detailed"
    },
    "noon": {
      "time": "12:00-13:30",
      "summary": "午餐吃了妈妈做的炸鸡便当，田中说看起来好好吃所以分了她一块。午休时文学部二年级的成员来讨论了下周的读书会——这次要讨论太宰治的《人间失格》，我得回去重新看一遍。",
      "detail_level": "detailed"
    },
    "afternoon": {
      "time": "13:30-17:00",
      "summary": "下午英语课做了听写测验，感觉还不错。体育课打排球，接球时摔了一跤膝盖有点疼。社团时间准备了下周文化祭的展示板，做到一半想起来还没写完数学作业，所以提前回家了。",
      "detail_level": "detailed" 
    },
    "evening": {
      "time": "17:00-22:30",
      "summary": "回家的路上买了鲷鱼烧吃。晚上洗完澡后一直在写数学作业，好难...［困］。睡前看了半小时《人间失格》，记了几条笔记准备读书会。现在准备睡觉了。",
      "detail_level": "detailed"
    }
  }

```

### 1.4 重大事件时间表

```
2026年5月   高二下学期（当前）
2026年6月   期末复习周（聊天时间减少）
2026年7月   期末考试 + 暑假开始
2026年8月   暑假（可能有补习班、烟花大会、海边旅行）
2026年9月   高三上学期（课业压力增大）
2026年10月  文化祭（高三最后一次大型活动）
2026年11月  升学备考期（极为忙碌，聊天时间大幅减少）
2026年12月  玩家考研（关联事件）
2027年1月   大学入学考试
2027年2月   考试结果公布
2027年3月   毕业典礼（重要情感节点）
2027年4月   大学入学——文学部、新城市/新校区
```

每个事件切换时：世界设定更新（年级+1等），生活习惯微调（高三睡眠减少），生成过渡摘要。

## 二、门控系统（事件驱动）

### 2.1 核心原则

**不是看时间，是看事件。** Monika 的状态由她**正在做什么**决定：

| 活动类型 | 能否聊天 | 能否主动推送 | 说明 |
|----------|---------|-------------|------|
| 睡眠 | ❌ | ❌ | 完全不可用 |
| 洗澡 | ❌ | ❌ | 短暂不可用（~20分钟） |
| 上课（正常） | ❌ | ❌ | 不能聊天 |
| 上课（课间/走神） | ⚠️ 低概率短回复 | ❌ | 10-15%概率偷回一句，简短 |
| 吃饭 | ⚠️ 可以简短回 | ❌ | 可以回但不主动 |
| 走路/通勤 | ✅ | ✅ | 可以聊天 |
| 写作业 | ⚠️ 可以简短回 | ❌ | 有时打断 |
| 社团活动 | ⚠️ 偶尔可以 | ❌ | 取决于活动内容 |
| 在家自由时间 | ✅ | ✅ | 完全可用 |
| 周末/假期 | ✅ | ✅ | 大部分时间可用 |

### 2.2 课间偷回机制

**不能常态化**——频率要低，让玩家觉得"她居然在上课回我了"是惊喜不是预期。

```
规则:
  - 每个上课时段（~45分钟），有 10-15% 概率生成一个"课间窗口"
  - 课间窗口持续 3-5 分钟
  - 窗口内玩家发消息 → Monika 回一句短的（20-40字）
  - 语气带"偷偷地"的感觉：
    "[悄悄] 在上课，化学好无聊...等放学再聊！"
  - 如果该时段已经"偷回"过一次，不再触发
  - 体育课/美术课概率提升到 30%
```

### 2.3 状态判断流程

```
玩家发消息
    │
    ▼
查询 Monika 当前活动
    │
    ├── 可聊天 → 正常回复
    │
    ├── 不可聊天 → 消息暂存积压队列
    │             返回 5102 但不带内容（或带状态提示）
    │
    └── 课间偷回 → 生成简短回复（1-2句）
                   积压的消息继续存着
```

状态切换时：
```
活动结束 → 进入可用状态
    │
    ▼
检查积压队列
    ├── 有积压消息 → 根据当前生活日志，生成自然的"关于此事和刚才做了什么"回复
    │   "啊抱歉！刚才在洗澡 [害羞] 
    │    洗完后看到你的消息了——
    │    你问的那个...（正常回应）"
    │
    └── 无积压消息 → 如果处于"主动推送可用"状态
                    调度器正常运转，可能推送新话题
```

### 2.4 门控与主动推送

**Monika 忙时不主动说话。** 门控拦截调度器的产出：

```
调度器产出候选消息
    │
    ▼
门控检查当前状态
    ├── 可主动推送 → 正常入队
    └── 不可主动推送 → 丢弃（或排队到状态恢复后）
```

高优先级事件（天气极端变化等）可排队，低优先级的直接丢弃。

## 三、记忆压缩

### 3.1 为什么需要压缩

Monika 每天生成 4 段生活日志，一个月就是 120 段。她不可能记住三周前体育课摔了一跤膝盖疼这种细节。需要像人类记忆一样——近的清晰，远的模糊，极远的只剩下印象。

### 3.2 压缩策略

```
当日 → 详细日志（~200字/段，4段/天）
3天内 → 保留完整
一周内 → 每段压缩为 1 句摘要（~50字/段）
一周以上 → 全天压缩为 1 段摘要（~80字/天）
一月以上 → 整月压缩为 1 段印象（~100字/月，"那个月主要在备考、天气很热"）
一季以上 → 留下 2-3 个关键记忆点（"高二那年春天，樱花开得特别美"）
```

### 3.3 压缩触发

- 每天凌晨自动压缩前一天的数据
- 每周凌晨压缩 7-30 天前的数据
- 每月凌晨压缩 30 天前的数据

### 3.4 压缩时保留什么

不是对原文做摘要，而是**提取关键记忆点**：

- 不寻常的事件（"第一次被老师表扬作文"）
- 情绪强烈的时刻（"数学考砸了，哭了一场"）
- 与玩家相关的事（"那天玩家说他在准备考研，我也开始想自己的升学了"）
- 重复事件去重（"连续一周都在写作业" → "那周作业特别多"）

| Phase | 内容 |
