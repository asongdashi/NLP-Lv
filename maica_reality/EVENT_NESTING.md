# 大事件-小事件嵌套结构

## 设计

大事件确定 Time Slot（时间锚），小事件填充该时段的内容。

```
大事件: 15:00-17:00 图书馆打工 (打工)
  ├── 小事件: 15:00 前台上岗，帮一个同学查了《源氏物语》的书号
  ├── 小事件: 15:30 整理文学区书架，发现一本被翻烂的《挪威的森林》
  ├── 小事件: 16:00 没什么人，闲着拿草稿本写了几行诗
  ├── 小事件: 16:30 帮一个教授调了论文数据库
  └── 小事件: 16:50 收工前整理还书，和轮班的同事交接
```

## 大事件 vs 小事件

| | 大事件 | 小事件 |
|---|---|---|
| 时间 | LLM 生成的固定 time-end | 大事件内部的相对时间 |
| 活动名 | 标准活动名 (上课90分钟/打工/社团活动) | 自由文本 |
| 数量 | 每天 ~25 个 | 每日大事件中各有 3-8 个小事件 |
| 参与人 | 主要参与者 | 具体互动的人 |

## 大事件类型（不变）

```
起床洗漱, 准备早饭, 做早饭, 吃早饭, 去上课, 上课90分钟, 上课45分钟,
去食堂, 吃午饭, 午休, 去图书馆, 图书馆学习, 打工, 去社团, 社团活动,
运动, 吃晚饭, 洗澡, 写作业, 自由阅读, 弹钢琴, 看手机, 写日记,
和室友聊天, 洗漱准备睡, 回宿舍, 睡觉
```

## 上下文注入规则

```
当前时间: 08:25
当前大事件: 上课90分钟 (08:15-09:45)

注入内容:
  ✅ 08:15 大事件开始 — 正在上课
  ✅ sub_event[0]: "教授开始讲《心》的创作背景" (08:15, ≤现在)
  ❌ sub_event[1]: "讨论先生和K的关系，我举手发了言" (08:40, 未来!)
  ❌ sub_event[2+3] 也不注入

Monika 看到的上下文:
  【你此刻正在做这件事】上课90分钟（近代文学课）
  【刚才发生的事】教授开始讲《心》的创作背景
```

**核心规则**: 小事件按 `sub_event.time ≤ now` 注入，只注入已经发生的。大事件进行中但小事件未到的不注入。

## 与现有代码的差异

| 改动 | 位置 |
|------|------|
| LLM prompt 增加 sub_events 字段 | `_generate_events` |
| 上下文注入按 sub_event.time 过滤 | `_get_proactive_context` |
| 验证加小事件时间必须在大事件区间内 | `_validate` |
| 小事件之间不能有时间重叠 | `_validate` |

## 好处

1. **不未卜先知**: 08:25 时只知道这节课已经讲了什么，不知道后面会讲什么
2. **对话更丰富**: "刚才讲完创作背景，现在在讲先生和K的关系" 比 "在上课" 有细节
3. **渐进式披露**: 随着时间推进，Monika 逐段解锁课程内容，像真实体验
